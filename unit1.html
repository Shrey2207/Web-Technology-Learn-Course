1. Introduction to World Wide Web (WWW)

What is the World Wide Web?

The World Wide Web (WWW), commonly known as the Web, is a collection of interconnected web pages and resources that can be accessed through the Internet. It allows users to find, view and share information using hyperlinks.

Web pages may contain text, images, audio, videos, animations and other multimedia content. Users access these resources through web browsers.

Key Characteristics of WWW

  • Global Connectivity: Connects users and information from different parts of the world.
  • Hyperlink Navigation: Links connect one web page to another.
  • Multimedia Support: Supports text, images, audio, video and animations.
  • Information Sharing: Allows users to publish and access information.
  • Easy Accessibility: Web resources can be accessed using devices connected to the Internet.
  • Interactivity: Users can interact with websites through forms, buttons and other elements.

History of WWW

The World Wide Web was invented by Tim Berners-Lee in 1989 while working at CERN (European Organization for Nuclear Research). Its original purpose was to help researchers share information easily.

The first website was hosted at CERN and explained information about the World Wide Web project.

Important: The World Wide Web Consortium (W3C) was established to develop common standards and guidelines for the Web.

Evolution of the Web

Web Version Description Main Features
Web 1.0 Read-only Web Static pages and one-way information sharing.
Web 2.0 Read and Write Web Social media, blogs, comments and user-generated content.
Web 3.0 Semantic Web Machine-understandable data and more personalised services.
Web 4.0 Intelligent Web Emerging ideas involving AI, connected systems and intelligent services.

2. Internet and WWW Architecture

What is a Web Browser?

A web browser is software used to access and display web pages. It sends requests to web servers, receives resources and displays them in a readable format.

Examples: Google Chrome, Mozilla Firefox, Microsoft Edge, Safari and Opera.

Functions of a Web Browser

  • Opens and displays websites.
  • Interprets HTML and CSS.
  • Executes JavaScript code.
  • Supports images, audio and video.
  • Stores cookies and cached resources.
  • Provides navigation through links and browser history.

Client-Server Architecture

The Web works mainly on a client-server architecture. The client is usually a web browser that sends a request. The server receives the request, processes it and sends a response.

Example:

When a user opens a website, the browser requests the website's files from the server. The server returns HTML, CSS, JavaScript and other resources. The browser then displays the website.

Internet vs. World Wide Web

Internet World Wide Web
A global network of interconnected computers and devices. A collection of linked information and web resources.
Provides the network infrastructure. Uses the Internet to provide access to websites.
Uses TCP/IP and other networking technologies. Uses technologies such as HTTP, HTML and URLs.
Supports email, file transfer and the Web. Provides web pages, websites and web applications.
Remember: The Internet is the infrastructure, while the World Wide Web is a service that operates on that infrastructure.

Web Browser vs. Web Server

Web Browser Web Server
Runs on the user's device. Runs on a server computer.
Sends requests for web resources. Receives and processes requests.
Displays web pages. Delivers web pages and other resources.
Examples: Chrome and Firefox. Examples: Apache and Nginx.

3. HTTP Protocol and Communication

What is HTTP?

HTTP stands for Hypertext Transfer Protocol. It is an application-layer protocol used for communication between web browsers and web servers.

HTTP defines how requests are sent by clients and how responses are returned by servers.

HTTP Request Structure

An HTTP request generally contains three main parts:

  1. Request Line: Contains the method, requested path and HTTP version.
  2. Headers: Provide additional information about the request.
  3. Body: Contains data sent to the server, such as form data or JSON.
Example of an HTTP Request: 
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Chrome
Accept: text/html

HTTP Request Methods

Method Purpose
GET Retrieves information from a server.
POST Sends data to a server.
PUT Creates or replaces a resource.
DELETE Deletes a specified resource.

HTTP Request Headers

  • Host: Identifies the requested server.
  • User-Agent: Provides information about the browser or client.
  • Accept: Specifies the content types the client can accept.
  • Content-Type: Describes the type of data being sent.
  • Authorization: Carries authentication information when required.

HTTP Response Structure

An HTTP response contains:

  1. Status Line: Contains HTTP version, status code and status message.
  2. Response Headers: Provide information about the response.
  3. Response Body: Contains the requested content or result.
Example of an HTTP Response: 
HTTP/1.1 200 OK
Content-Type: text/html
Cache-Control: max-age=3600




Welcome

HTTP Status Codes

Code Meaning
200 OK – Request completed successfully.
301 Moved Permanently – Resource has a new location.
400 Bad Request – The request is invalid.
401 Unauthorized – Authentication is required or has failed.
403 Forbidden – Access is not allowed.
404 Not Found – Requested resource does not exist.
500 Internal Server Error.
503 Service Unavailable.

HTTP Request-Response Lifecycle

  1. DNS Resolution: The browser finds the IP address associated with the domain name.
  2. TCP Connection: A connection is established between the client and server when TCP is used.
  3. HTTP Request: The browser sends an HTTP request to the server.
  4. Server Processing: The server processes the request and prepares the response.
  5. HTTP Response: The server sends the result back to the browser.
  6. Connection Management: The connection may close or remain available for further requests.

TCP Three-Way Handshake

TCP uses a three-way handshake to establish a reliable connection between two devices.

  1. SYN: The client requests to start a connection.
  2. SYN-ACK: The server acknowledges the request and responds.
  3. ACK: The client acknowledges the server's response.

HTTP vs. HTTPS

HTTP HTTPS
Hypertext Transfer Protocol. Hypertext Transfer Protocol Secure.
Does not itself provide encryption. Uses TLS to protect communication.
Commonly uses port 80. Commonly uses port 443.
Less suitable for sensitive information. Protects data from interception and tampering in transit.

4. URL, URI and Domain Names

What is a URL?

URL stands for Uniform Resource Locator. It is the address used to locate a resource on the Internet.

Example: 
https://www.example.com/about.html

Components of a URL

  • Scheme: Defines the protocol, such as HTTP or HTTPS.
  • Subdomain: A subdivision of the main domain, such as www.
  • Domain Name: The main name of the website.
  • Top-Level Domain: The ending such as .com, .org or .in.
  • Path: Identifies a particular page or resource.

URI, URL and URN

URI stands for Uniform Resource Identifier. It is a general term used to identify a resource. A URL is a type of URI that also provides its location. A URN identifies a resource using a unique name.

URI URL URN
Identifies a resource. Identifies and locates a resource. Identifies a resource by name.
General category. Type of URI. Type of URI.
May or may not specify a location. Provides a location and access method. Does not need to specify a location.
Examples: 
URL: https://www.example.com
URN: urn:isbn:978-0-395-36341-6

IP Address vs. Domain Name

An IP address is a numerical address used to identify a device on a network. A domain name is a human-readable name associated with an IP address through DNS.

Domain Name Structure

A domain name is made up of labels separated by dots. For example, in www.example.com, the labels are www, example and com.

Top-Level Domains (TLDs)

  • .com: Commonly used for commercial websites.
  • .org: Commonly used by organisations.
  • .net: Originally associated with network services.
  • .edu: Used for eligible educational institutions, especially in the United States.
  • .gov: Used for government entities in designated domains.
  • .in: Country-code top-level domain for India.

Labels and Subdomains

A label is an individual part of a domain name. Subdomains are created under a main domain to organise different sections or services.

Examples: 
www.example.com
support.example.com
blog.example.com
developer.example.com

Domain Registration

Domain names are registered through domain registrars. A user pays for the right to use a domain for a specified period and can renew the registration.

Note: Domain registration is generally a renewable right to use a name, not permanent ownership of it. ICANN coordinates the global domain name system and policies with registries and registrars.

5. Browser and Server Architecture

How a Browser Works

A browser receives website resources from a server, interprets the code and displays the final page to the user.

Browser Rendering Process

  1. The browser downloads the HTML document.
  2. HTML is parsed to create the DOM tree.
  3. CSS is parsed to create the CSSOM tree.
  4. The browser combines layout information.
  5. Elements are painted and displayed on the screen.
  6. JavaScript can update the page and change its content.

DOM and CSSOM

DOM (Document Object Model): A tree-like representation of the HTML document. JavaScript can use it to access and change page elements.

CSSOM (CSS Object Model): A representation of the CSS rules applied to a web page.

Browser Engines

  • Blink: Used by Chrome and several Chromium-based browsers.
  • Gecko: Used by Mozilla Firefox.
  • WebKit: Used by Safari.

JavaScript Engines

  • V8: Used by Chrome and other Chromium-based environments.
  • SpiderMonkey: Used by Firefox.

Browser Storage and Caching

  • Cache: Stores copies of resources to help pages load faster.
  • Cookies: Small pieces of data used for sessions and preferences.
  • LocalStorage: Stores key-value data in the browser for later use.

Web Server Architecture

A web server listens for incoming requests, processes them and returns web resources. It may serve static files directly or forward requests to an application.

Common Web Servers

Apache Nginx
Popular open-source web server. Popular high-performance web server and reverse proxy.
Supports different process and thread models. Uses an event-driven, asynchronous architecture.
Can serve websites and handle application requests. Can serve static files, proxy requests and manage many connections efficiently.

6. IP Addressing

What is an IP Address?

IP stands for Internet Protocol. An IP address is a numerical identifier assigned to a network interface. It helps devices send and receive data across networks.

How Does an IP Address Work?

  1. It identifies a network interface.
  2. It helps determine where data should be sent.
  3. Routers examine IP information to forward packets.
  4. The destination device receives the data.

IPv4 Address

IPv4 is the fourth version of the Internet Protocol. It uses a 32-bit address divided into four groups separated by dots.

Example: 
192.168.1.10

Each group is called an octet and has a decimal value from 0 to 255. IPv4 supports approximately 4.3 billion possible addresses.

IPv6 Address

IPv6 is the newer version of the Internet Protocol. It uses 128-bit addresses written in hexadecimal groups separated by colons.

Example: 
2001:db8:8b73::8a2e:370:1337

IPv6 provides a vastly larger address space and supports the continued growth of connected devices.

IPv4 vs. IPv6

Feature IPv4 IPv6
Address Size 32 bits 128 bits
Format Decimal numbers separated by dots. Hexadecimal groups separated by colons.
Address Space About 4.3 billion addresses. Approximately 3.4 × 10³⁸ addresses.
Configuration Manual configuration or DHCP. Manual configuration, SLAAC or DHCPv6.
Broadcast Supports broadcast. Uses multicast and anycast instead.
Header Variable length. Fixed 40-byte base header.

Drawbacks of IPv4

  • Limited address space.
  • Increasing demand from connected devices.
  • Use of NAT in many networks to share public IPv4 addresses.
  • Broadcast traffic can create unnecessary network load.
  • Security and traffic-management features require appropriate configuration and supporting protocols.

Benefits of IPv6

  • Very large address space.
  • Simplified base header.
  • Support for automatic address configuration.
  • Uses multicast and anycast instead of broadcast.
  • Designed to support modern network growth.

IPv4 and IPv6 Transition

  • Dual Stack: A device runs IPv4 and IPv6 together.
  • Tunneling: One IP version is carried inside packets of another version.
  • Translation: Gateway technologies translate between IPv4 and IPv6 where needed.

Types of IP Addresses

Type Meaning
Public IP An address used for communication across the public Internet.
Private IP An address used within a private network.
Static IP An address configured to remain unchanged unless manually or administratively changed.
Dynamic IP An address assigned automatically, commonly through DHCP, and may change over time.
Important: Public/private describes where an address is used. Static/dynamic describes how its assignment is managed. These are two separate classifications.

Public IP Address

A public IP address is used for communication over the public Internet. An Internet Service Provider commonly assigns one to a home or business router.

Private IP Address

A private IP address is used inside a local network. It allows devices such as laptops, phones and printers to communicate with each other.

Private IPv4 ranges:

  • 10.0.0.0 to 10.255.255.255
  • 172.16.0.0 to 172.31.255.255
  • 192.168.0.0 to 192.168.255.255

Static IP Address

A static IP address is configured to remain constant. It is useful for servers and network services that need a predictable address.

Dynamic IP Address

A dynamic IP address is assigned automatically, usually by a DHCP server. It may change when a lease expires or a network reconnects.

DHCP (Dynamic Host Configuration Protocol)

DHCP automatically provides network configuration information to devices. This can include an IP address, subnet mask, default gateway and DNS servers.

Reserved IPv4 Addresses

Address or Range Purpose
0.0.0.0 Unspecified address; meaning depends on context.
127.0.0.1 Loopback address used by a device to communicate with itself.
169.254.0.0/16 Link-local address range, often used when DHCP configuration fails.
255.255.255.255 Limited broadcast address.

IP Address Classes

Traditional classful addressing divided IPv4 addresses into classes. Modern networks generally use CIDR (Classless Inter-Domain Routing) and prefix lengths.

Class Range Purpose
A 1.0.0.0 – 126.255.255.255 Historically used for very large networks.
B 128.0.0.0 – 191.255.255.255 Historically used for medium-sized networks.
C 192.0.0.0 – 223.255.255.255 Historically used for smaller networks.
D 224.0.0.0 – 239.255.255.255 Multicast.
E 240.0.0.0 – 255.255.255.255 Reserved and experimental uses, with special-purpose exceptions.

Subnetting

Subnetting divides a large network into smaller networks called subnets. A subnet mask or prefix identifies which part of an IP address represents the network and which part represents the host.

Example: 
IP Address: 192.168.1.10
Subnet Mask: 255.255.255.0
CIDR Prefix: /24

In this example, the first 24 bits identify the network portion.

IP Address vs. MAC Address

IP Address MAC Address
Identifies a network interface at the IP layer. Identifies a network interface at the link layer.
Used for routing packets between networks. Used for communication on a local network link.
Can change when network configuration changes. Usually assigned to the network interface by its manufacturer, though it can be changed or randomised by software.
IPv4 or IPv6 format. Commonly represented as hexadecimal pairs.

How to Find Your IP Address

On Windows

  1. Open the Start menu.
  2. Search for Command Prompt or type cmd.
  3. Enter the command ipconfig.
  4. Check the IPv4 Address under your active network adapter.
ipconfig

On macOS

Open System Settings, select Network and choose your active connection to view its IP information.

On Mobile Devices

Open Settings, select Wi-Fi or Network, choose the connected network and view its details.

Security Threats Related to IP Addresses

  • Location Exposure: An IP address may reveal an approximate location.
  • DDoS Attacks: Attackers may flood a network or service with traffic.
  • Online Tracking: IP addresses can be used as one signal for tracking activity.
  • Impersonation and Abuse: Attackers may misuse an exposed network address or attempt to exploit services running on it.

Ways to Protect Your IP Address

  • Use a trusted VPN when appropriate.
  • Keep router firmware and devices updated.
  • Use a firewall to restrict unwanted connections.
  • Secure Wi-Fi with a strong password and modern encryption.
  • Disable services and ports that are not required.
  • Use NAT for appropriate private-network connectivity, while remembering that NAT is not a replacement for a firewall.

7. Web 2.0 and Modern Web Technologies

What is Web 2.0?

Web 2.0 describes the development of interactive websites and applications where users can create, share and collaborate on content.

Unlike the mostly read-only websites of Web 1.0, Web 2.0 encourages participation and communication.

Features of Web 2.0

  • User-generated content.
  • Social networking and online communities.
  • Comments, reviews and ratings.
  • Interactive web applications.
  • Sharing and collaboration.

AJAX (Asynchronous JavaScript and XML)

AJAX is a technique that allows a web page to communicate with a server in the background without reloading the entire page.

Despite its name, AJAX can exchange JSON and other data formats, not only XML.

Advantages of AJAX

  • Updates parts of a page without a full reload.
  • Can improve the user experience.
  • Allows background data requests.
  • Helps build interactive web applications.
Example using Fetch API: 
fetch("https://example.com/data")
.then(response => response.json())
.then(data => {
    console.log(data);
});

User-Generated Content

User-generated content is information created and shared by users rather than only by website owners.

Examples include social media posts, blog comments, product reviews, videos and discussion forums.

RESTful APIs

REST stands for Representational State Transfer. It is an architectural style used to design web APIs. REST APIs commonly use HTTP methods to work with resources.

  • GET – Retrieve data.
  • POST – Create or submit data.
  • PUT – Replace or update a resource.
  • DELETE – Remove a resource.

JSON

JSON stands for JavaScript Object Notation. It is a lightweight format used to exchange structured data between applications.

Example of JSON: 
{
    "name": "Shrey",
    "course": "B.Tech CSE",
    "year": 1
}

Software as a Service (SaaS)

SaaS is a software delivery model in which applications are hosted by a service provider and accessed over the Internet, often through a web browser.

Examples: Google Docs, Microsoft 365 and Figma.

8. Dynamic IP and Dynamic DNS (DDNS)

Static IP vs. Dynamic IP

A static IP address remains the same unless it is changed manually or administratively. A dynamic IP address is assigned automatically and may change over time.

DHCP and Dynamic IP

DHCP stands for Dynamic Host Configuration Protocol. It automatically assigns IP addresses and other network settings to devices.

What is Dynamic DNS?

DDNS stands for Dynamic Domain Name System. It is a service that updates DNS records when a device's public IP address changes.

Why is DDNS Required?

A normal DNS record often points a domain name to a known IP address. If a home or small business server uses a dynamic public IP, that address may change. The old DNS record may then point to the wrong address.

DDNS solves this problem by updating the DNS record when the public IP changes.

How DDNS Works

  1. A device or router receives a public IP address.
  2. A DDNS client monitors the current public IP.
  3. If the IP changes, the client contacts the DDNS provider.
  4. The provider updates the domain's DNS record.
  5. Users can continue using the same domain name.
Example: A person hosts a small website at home. Their ISP changes the public IP address. A DDNS service updates the domain record so visitors can still use the same domain name.

Advantages of DDNS

  • Provides a consistent domain name for a changing IP.
  • Useful for home servers and remote access.
  • Reduces the need for manual DNS updates.
  • Can be configured on compatible routers or servers.
Remember: DDNS updates DNS records. It does not make a dynamic IP static and does not automatically configure firewall rules or make a server secure.

9. Web Design Fundamentals

What is Web Design?

Web design is the process of planning and creating the layout, appearance and user experience of a website. It includes visual design, navigation, accessibility and usability.

UI and UX

UI (User Interface): The visual and interactive parts of a website, such as buttons, menus, colours and forms.

UX (User Experience): The overall experience a person has while using a website or application.

Core Principles of UI/UX

  • User-Centricity: Design should focus on the needs of users.
  • Consistency: Similar elements should behave and look alike.
  • Simplicity: Avoid unnecessary complexity.
  • Accessibility: Make the website usable by people with different abilities.
  • Feedback: Show clear responses when users interact with controls.

Visual Hierarchy

Visual hierarchy is the arrangement of elements to guide the user's attention toward the most important information first.

It can be created using:

  • Different font sizes.
  • Bold and regular text.
  • Colour and contrast.
  • Spacing and alignment.
  • Position and grouping of elements.

F-Pattern and Z-Pattern

Users often scan web pages instead of reading every word. The F-pattern describes a common scanning behaviour where attention is concentrated near the top and left side of a page.

The Z-pattern describes a possible scanning path across visually simple landing pages, moving from the top-left to top-right, diagonally down and then across the bottom.

Navigation and Website Structure

Navigation helps users find information and move between different pages.

  • Use clear navigation menus.
  • Organise content into meaningful sections.
  • Use descriptive links.
  • Provide breadcrumbs on larger websites where useful.
  • Keep navigation consistent across pages.

Responsive Web Design (RWD)

Responsive Web Design is an approach in which a website adjusts its layout and content to fit different screen sizes and devices.

Techniques Used in RWD

  • Flexible layouts and fluid grids.
  • CSS media queries.
  • Flexible images and content.
  • Flexbox and CSS Grid.
  • Mobile-first design.
Example of a Media Query: 
@media (max-width: 600px) {
    body {
        font-size: 14px;
    }

    .container {
        width: 100%;
    }
}

Accessibility and WCAG

Web accessibility means designing websites so that people with disabilities can use them. WCAG stands for Web Content Accessibility Guidelines.

  • Provide alternative text for meaningful images.
  • Use sufficient colour contrast.
  • Make links and buttons usable with a keyboard.
  • Use clear headings and labels.
  • Provide captions for important video content.
  • Use semantic HTML elements.

Cross-Browser Compatibility

Cross-browser compatibility means ensuring that a website works correctly across different browsers.

Browsers may use different rendering engines and support features differently. Developers should test their websites in multiple browsers and use standard web technologies.

Website Performance and Speed

Website performance refers to how quickly and smoothly a website loads and responds to user actions.

Ways to Improve Performance

  • Compress and optimise images.
  • Minify CSS and JavaScript files.
  • Use browser caching.
  • Reduce unnecessary requests.
  • Use a Content Delivery Network (CDN) where appropriate.
  • Load non-critical resources efficiently.

Core Web Vitals

  • LCP (Largest Contentful Paint): Measures loading performance.
  • INP (Interaction to Next Paint): Measures responsiveness to interactions.
  • CLS (Cumulative Layout Shift): Measures unexpected layout movement.

Common Web Design Issues

  • Slow Loading: Large files and unnecessary code make pages slow.
  • Mobile Unresponsiveness: Pages may not fit smaller screens.
  • Cluttered Layout: Too many elements make content difficult to understand.
  • Poor Accessibility: Low contrast and missing labels can prevent users from accessing information.
  • Broken Links: Links may lead to missing pages.
  • Technical Errors: Outdated code and server problems can affect usability.
  • Security Problems: Poorly protected websites can expose users and data to attacks.

Security Considerations in Web Design

  • Protect user input against Cross-Site Scripting (XSS).
  • Use HTTPS for secure communication.
  • Apply appropriate Content Security Policy (CSP) headers.
  • Use secure authentication and session management.
  • Protect sensitive pages against clickjacking.

Web Design Best Practices

  1. Start with a mobile-friendly layout.
  2. Keep the design clean and consistent.
  3. Use readable fonts and suitable colours.
  4. Provide clear navigation.
  5. Optimise images and other resources.
  6. Follow accessibility guidelines.
  7. Test the website on different devices and browsers.
  8. Keep the website secure and updated.

10. Linux Web Server Setup

What is a Linux Web Server?

A Linux web server is a computer or virtual machine running Linux and web server software. It receives HTTP or HTTPS requests and delivers website content to users.

Apache and Nginx

Apache and Nginx are widely used web server applications. Both can serve static website files and support configurations for hosting websites.

Step 1: Update the Package Manager

On Debian or Ubuntu, update the package information before installing software. 

sudo apt update

Step 2: Install Apache

sudo apt install apache2

To start Apache and enable it at system startup: 

sudo systemctl start apache2
sudo systemctl enable apache2

Alternative: Install Nginx

sudo apt install nginx
sudo systemctl start nginx
sudo systemctl enable nginx
Note: Apache and Nginx are alternatives for many basic deployments. You normally do not need to install both for a simple website.

Step 3: Document Root and Permissions

The document root is the directory from which the web server serves website files. A common default location on Ubuntu is: 

/var/www/html

Permissions must be configured so that the web server can read the website files safely. 

sudo chown -R www-data:www-data /var/www/html

Step 4: Virtual Host Configuration

Virtual hosts allow a single web server to host multiple websites using different domain names.

Apache site configuration files are commonly stored in: 

/etc/apache2/sites-available/

A site can be enabled with the following commands: 

sudo a2ensite example.conf
sudo systemctl reload apache2

Step 5: Firewall Configuration

A firewall controls which network connections are allowed to reach a server. 

sudo ufw allow OpenSSH
sudo ufw allow 'Apache Full'
sudo ufw enable

For Nginx, use the suitable Nginx firewall profile instead of the Apache profile.

Step 6: SSL and HTTPS Setup

SSL is the older name commonly used when discussing secure web certificates. Modern HTTPS uses TLS. Certificates help authenticate a website and enable encrypted connections.

Let's Encrypt provides free TLS certificates. Certbot can help obtain and configure certificates. 

sudo apt install certbot python3-certbot-apache
sudo certbot --apache
Important: Use the Nginx Certbot integration when configuring Nginx. Before enabling HTTPS, ensure the domain points to the server and the required ports are reachable.
