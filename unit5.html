XML stands for Extensible Markup Language. It is used to represent, store and transport structured data. This unit explains XML document structure, syntax rules, namespaces, validation using DTD and XML Schema, and transformation using XPath and XSLT.

1. Introduction to XML

What is XML?

XML stands for Extensible Markup Language. It is a text-based markup language used to represent, store and transport structured information.

XML allows users to create their own tags according to the type of information they want to store. It describes the meaning and structure of data rather than how the data should look on a web page.

Example of XML

<course code="WT205">

    <title>Web Technologies</title>

    <credits>4</credits>

    <instructor>Dr. Mehta</instructor>

</course>

In this example, course, title, credits and instructor are XML elements. The information is stored in a structured format using meaningful tags.

Why is XML Used?

  • To store structured information.
  • To exchange data between different applications.
  • To transport information between systems.
  • To create configuration files.
  • To represent information in a readable format.
  • To organise data using meaningful tags.

Features of XML

A. Extensible

XML allows users to create their own tags. It does not have a fixed set of tags like HTML.

B. Structured

XML stores information in a tree structure. Elements can contain other elements, creating parent-child relationships.

C. Portable

XML is plain text and can be read by people and processed by software on different operating systems and platforms.

D. Platform Independent

XML can be exchanged between different systems without depending on a particular operating system or programming language.

E. Self-Descriptive

XML uses meaningful tag names that describe the information being stored.

F. Data-Oriented

XML focuses on representing and carrying data. It does not automatically provide a visual design or user interface.

Difference Between HTML and XML

HTML XML
HTML stands for HyperText Markup Language. XML stands for Extensible Markup Language.
HTML is used to display and structure web pages. XML is used to store and transport structured data.
HTML has predefined tags. XML allows users to create their own tags.
HTML tags have predefined meanings. XML tags describe the meaning of data.
HTML is generally more forgiving about syntax. XML follows strict syntax rules.
HTML focuses on presentation and document structure. XML focuses on data representation and structure.

Where is XML Used?

  • Data Exchange: Sharing information between different applications.
  • Configuration Files: Storing application settings.
  • RSS Feeds: Sharing updates and news articles.
  • Document Formats: Representing structured documents.
  • Web Services: Exchanging information between systems.
  • Data Storage: Organising information in a structured format.
Remember: XML is a data format, not a programming language. It describes what information means, while another application or stylesheet decides how to use or display that information.

2. XML Key Components and Document Structure

XML Document Structure

An XML document is organised as a tree of nodes. It contains a single root element and may include nested elements, attributes, text and comments.

Example of an XML Document

<?xml version="1.0" encoding="UTF-8"?>

<student id="s204" status="active">

    <name>Mira Shah</name>

    <programme>B.Tech CSE</programme>

    <marks subject="XML">88</marks>

    <!-- A student record -->

</student>

This example contains an XML declaration, a root element, child elements, attributes, text nodes and a comment.

A. XML Declaration

The XML declaration is an optional statement written at the beginning of an XML document. It specifies the XML version and character encoding. 

<?xml version="1.0" encoding="UTF-8"?>

Important parts:

  • version: Specifies the XML version, commonly 1.0.
  • encoding: Specifies the character encoding, commonly UTF-8.

B. Elements

Elements are the basic building blocks of XML. An element usually consists of a start tag, content and an end tag. 

<name>Mira Shah</name>

Here, name is the element name and Mira Shah is its content.

C. Root Element

The root element is the single outermost element of an XML document. All other elements must be contained inside it. 

<student>

    <name>Mira</name>

    <age>20</age>

</student>

In this example, student is the root element.

D. Attributes

Attributes provide additional information about an element. They are written inside the start tag in name-value pairs. 

<student id="101" status="active">

    <name>Mira</name>

</student>

Here, id and status are attributes of the student element.

E. Text Nodes

Text nodes contain the actual character data written between an element's opening and closing tags. 

<marks>88</marks>

Here, 88 is the text content of the marks element.

F. Comments

Comments are used to add notes or explanations to an XML document. They are ignored as data by the XML application. 

<!-- This is a student record -->

G. Empty Elements

An empty element does not contain any text or child elements. It can be written using self-closing syntax. 

<image/>

<address/>

Summary of XML Components

Component Example Purpose
XML Declaration version="1.0" Identifies XML version and encoding.
Element <name>Mira</name> Stores a unit of information.
Root Element <student> Contains the entire document structure.
Attribute id="101" Provides additional information.
Text Node 88 Stores character data.
Comment <!-- Note --> Provides explanations in the document.

3. XML Syntax Rules and Well-Formed Documents

What are XML Syntax Rules?

XML follows strict syntax rules. Every XML document must follow these rules to be considered well-formed.

Important XML Syntax Rules

A. Every Opening Tag Must Have a Closing Tag

Each element must be properly closed, or written using self-closing syntax if it is empty. 

<name>Mira</name>

<image/>

B. XML Tags are Case-Sensitive

XML distinguishes between uppercase and lowercase letters. Therefore, the opening and closing tag names must match exactly. 

<Name>Mira</Name>

The tags Name and name are considered different names.

C. Proper Nesting of Elements

XML elements must be nested correctly. The inner element must close before the outer element closes.

Correct Example:

<student>

    <name>Mira</name>

</student>

Incorrect Example:

<student>

    <name>Mira</student>

</name>

D. Attribute Values Must Be Quoted

Every attribute value must be enclosed in single or double quotation marks.

Correct:

<student id="101">

Incorrect:

<student id=101>

E. Only One Root Element

An XML document must have exactly one document element or root element. Other elements must be placed inside it.

Correct:

<students>

    <student>Mira</student>

    <student>Asha</student>

</students>

F. Reserved Characters Must Be Escaped

Certain characters have special meanings in XML. When they are needed as ordinary text, predefined entity references must be used.

Character Entity Reference Meaning
& &amp; Ampersand
< &lt; Less than
> &gt; Greater than
" &quot; Double quotation mark
' &apos; Single quotation mark

Example of Escaping Characters

<message>

    Tom &amp; Jerry

    5 &lt; 10

    10 &gt; 5

</message>

The XML parser interprets these entity references as their corresponding characters.

What is a Well-Formed XML Document?

A well-formed XML document is one that follows all the basic XML syntax rules.

It must have:

  • Exactly one root element.
  • Properly opened and closed elements.
  • Correct nesting of elements.
  • Quoted attribute values.
  • Correct use of XML syntax and special characters.

Well-Formed XML Example

<student>

    <name>Asha</name>

    <course>B.Tech CSE</course>

    <marks>90</marks>

</student>

Well-Formed vs Valid XML

Well-formedness checks whether an XML document follows basic syntax rules. Validity checks whether the document also follows a declared grammar, such as a DTD or XSD.

Well-Formed XML Valid XML
Follows basic XML syntax rules. Follows basic syntax rules and a declared grammar.
Requires one root element. Also checks the expected document structure.
Checks correct nesting and closing tags. Can check element order, occurrence and data constraints.
Does not require a DTD or XSD. Requires conformance to a DTD or XSD grammar.
Important: Every valid XML document must be well-formed, but every well-formed XML document is not necessarily valid.

4. XML Namespaces and Reserved Characters

What are XML Namespaces?

XML namespaces are used to avoid naming conflicts when elements from different XML vocabularies are used together.

Two different applications may use the same element name for different purposes. Namespaces help identify which vocabulary an element belongs to.

Why are Namespaces Needed?

Suppose two systems use an element called title. One system uses title for a book title, while another uses it for a course title. If both are combined, the same name may create confusion.

Namespaces solve this problem by associating names with a unique namespace URI.

Namespace Declaration

The xmlns attribute is used to declare a namespace. A prefix can then be used to identify elements belonging to that namespace. 

<course xmlns:lib="https://example.edu/library">

    <title>Web Technologies</title>

    <lib:title>XML for Libraries</lib:title>

</course>

In this example:

  • xmlns:lib: Declares a namespace with the prefix lib.
  • lib: Is the namespace prefix.
  • title: Is the local element name.
  • Namespace URI: Identifies the vocabulary.

Default Namespace

A default namespace can be declared without using a prefix. Unprefixed elements within its scope belong to that namespace. 

<library xmlns="https://example.edu/library">

    <book>

        <title>Learning XML</title>

        <author>Asha Rao</author>

    </book>

</library>

Important Points About Namespaces

  • Namespaces prevent naming conflicts.
  • The xmlns attribute declares a namespace.
  • A prefix identifies elements belonging to a namespace.
  • The namespace URI identifies the vocabulary.
  • The URI does not have to be an active web page.
Remember: Namespaces are particularly useful when combining XML documents from different sources or applications.

5. DTD – Document Type Definition

What is DTD?

DTD stands for Document Type Definition. It defines the legal structure of an XML document. It specifies which elements and attributes are allowed and how elements can be arranged.

DTD is used to check whether an XML document follows a predefined structure.

Why is DTD Used?

  • To define allowed XML elements.
  • To specify the order of child elements.
  • To define how many times an element can appear.
  • To declare attributes.
  • To help validate XML documents.

Types of DTD

A. Internal DTD

An internal DTD is written directly inside the XML document using a DOCTYPE declaration. 

<?xml version="1.0"?>

<!DOCTYPE student [

    <!ELEMENT student (name, course)>

    <!ELEMENT name (#PCDATA)>

    <!ELEMENT course (#PCDATA)>

]>

<student>

    <name>Asha</name>

    <course>B.Tech CSE</course>

</student>

The declarations between square brackets define the allowed structure of the student document.

B. External DTD

An external DTD is stored in a separate file with the .dtd extension. The XML document connects to this file using a DOCTYPE declaration.

Step 1: Create catalog.dtd

<!ELEMENT catalog (product+)>

<!ELEMENT product (name, price)>

<!ATTLIST product id ID #REQUIRED>

<!ELEMENT name (#PCDATA)>

<!ELEMENT price (#PCDATA)>

Step 2: Create catalog.xml

<?xml version="1.0" encoding="UTF-8"?>

<!DOCTYPE catalog SYSTEM "catalog.dtd">

<catalog>

    <product id="p101">

        <name>Notebook</name>

        <price>45.50</price>

    </product>

    <product id="p102">

        <name>Pen Set</name>

        <price>30.00</price>

    </product>

</catalog>

The XML document refers to catalog.dtd. The DTD specifies that the catalog contains one or more product elements, each with a name followed by a price.

Understanding DTD Declarations

Declaration Meaning
<!ELEMENT> Declares an XML element.
<!ATTLIST> Declares attributes for an element.
<!DOCTYPE> Declares the document type and connects its grammar.
#PCDATA Parsed character data, usually text content.
#REQUIRED Makes an attribute compulsory.

DTD Occurrence Indicators

DTD uses special symbols to specify how often an element can occur.

Symbol Meaning
? Zero or one occurrence.
* Zero or more occurrences.
+ One or more occurrences.
, Elements must appear in the specified sequence.
| Allows a choice between alternatives.

Example of DTD Content Models

<!ELEMENT student (name, course)>

<!ELEMENT students (student+)>

<!ELEMENT nickname (#PCDATA)?>

These declarations mean:

  • student must contain name followed by course.
  • students must contain one or more student elements.
  • nickname may appear zero or one time and contains text.

Advantages of DTD

  • Simple way to define XML document structure.
  • Helps maintain consistency between XML documents.
  • Supports element and attribute declarations.
  • Can be stored internally or externally.

Limitations of DTD

  • DTD is not written using XML syntax.
  • It provides limited data types.
  • It has limited support for XML namespaces.
  • It does not provide the same detailed constraints as XSD.

6. XML Schema (XSD) and Validation

What is XML Schema?

XML Schema Definition, commonly called XSD, is used to define the structure and rules of an XML document. It specifies which elements and attributes are allowed, their data types and other restrictions.

XSD is written using XML syntax and provides more detailed validation features than DTD.

Why is XSD Used?

  • To define the structure of an XML document.
  • To specify data types for elements and attributes.
  • To control the order of elements.
  • To set minimum and maximum occurrences.
  • To apply restrictions to data values.
  • To validate XML documents more precisely.

Basic Structure of an XSD Document

<?xml version="1.0" encoding="UTF-8"?>

<xs:schema
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <!-- Schema declarations go here -->

</xs:schema>

The xs:schema element is the root element of an XML Schema document. The xs prefix refers to the XML Schema namespace.

Common XSD Data Types

Data Type Purpose Example
xs:string Stores text. Web Technologies
xs:integer Stores whole numbers. 25
xs:decimal Stores decimal numbers. 45.50
xs:boolean Stores true or false values. true
xs:date Stores a date. 2026-11-24
xs:time Stores a time. 10:30:00
xs:ID Stores an XML identifier. p101

Simple Types and Complex Types

A. Simple Type

A simple type contains only text data and does not contain child elements or attributes. 

<xs:element name="price" type="xs:decimal"/>

This declaration specifies that the price element must contain a decimal value.

B. Complex Type

A complex type can contain child elements and attributes. It is useful for representing structured records. 

<xs:element name="student">

    <xs:complexType>

        <xs:sequence>

            <xs:element name="name" type="xs:string"/>

            <xs:element name="age" type="xs:integer"/>

        </xs:sequence>

    </xs:complexType>

</xs:element>

Here, student contains two child elements: name and age.

Important XSD Elements

XSD Element Purpose
xs:schema Root element of the schema.
xs:element Declares an XML element.
xs:attribute Declares an attribute.
xs:complexType Defines a complex structure.
xs:simpleType Defines a simple data type.
xs:sequence Requires child elements in a particular order.
xs:choice Allows one choice from a group of elements.
xs:all Allows child elements in any order, subject to its occurrence rules.

Occurrence Constraints

XSD uses minOccurs and maxOccurs to control how many times an element can appear. 

<xs:element
    name="product"
    type="xs:string"
    minOccurs="1"
    maxOccurs="5"/>

This declaration allows the product element to appear at least once and at most five times.

Value Restrictions

XSD can restrict the values accepted by an element. Some common restriction elements include:

Restriction Purpose
xs:minInclusive Sets the minimum allowed value, including the boundary.
xs:maxInclusive Sets the maximum allowed value, including the boundary.
xs:minLength Sets the minimum length of a value.
xs:maxLength Sets the maximum length of a value.
xs:enumeration Allows only specified values.
xs:pattern Checks a value against a pattern.

Complete Example: Catalog XSD

The following schema defines a catalog containing products. Each product has a name, a decimal price and a required ID. 

<?xml version="1.0" encoding="UTF-8"?>

<xs:schema
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <xs:element name="catalog">

        <xs:complexType>

            <xs:sequence>

                <xs:element name="product"
                    maxOccurs="unbounded">

                    <xs:complexType>

                        <xs:sequence>

                            <xs:element
                                name="name"
                                type="xs:string"/>

                            <xs:element
                                name="price"
                                type="xs:decimal"/>

                        </xs:sequence>

                        <xs:attribute
                            name="id"
                            type="xs:ID"
                            use="required"/>

                    </xs:complexType>

                </xs:element>

            </xs:sequence>

        </xs:complexType>

    </xs:element>

</xs:schema>

XML Document Connected to XSD

An XML document can refer to an external schema using xsi:noNamespaceSchemaLocation when the schema does not use a target namespace. 

<?xml version="1.0" encoding="UTF-8"?>

<catalog
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:noNamespaceSchemaLocation="catalog.xsd">

    <product id="p101">

        <name>Notebook</name>

        <price>45.50</price>

    </product>

</catalog>

Difference Between DTD and XSD

DTD XSD
Document Type Definition. XML Schema Definition.
Uses specialised DTD syntax. Uses XML syntax.
Provides limited data types. Provides many built-in and custom data types.
Has limited namespace support. Designed to support XML namespaces.
Provides basic structural validation. Provides more detailed structural and value constraints.
Suitable for simple or legacy document formats. Useful when detailed validation and typed values are needed.

What is XML Validation?

XML validation is the process of checking whether an XML document follows the rules defined in a DTD or XSD.

Validation helps ensure that:

  • Only permitted elements are used.
  • Elements appear in the correct order.
  • Required attributes are present.
  • Data values follow the expected types and restrictions.

Using xmllint for Validation

The xmllint utility, provided by libxml2, can be used to validate XML documents from the command line.

DTD Validation:

xmllint --noout --valid catalog.xml

XSD Validation:

xmllint --noout --schema catalog.xsd catalog.xml

A successful validation indicates that the XML document conforms to the specified grammar.

Important: A normal XML parser checks whether a document is well-formed. Validation against a DTD or XSD requires a validating processor or suitable validation tool.

7. XPath – XML Path Language

What is XPath?

XPath stands for XML Path Language. It is used to navigate through an XML document and select specific elements, attributes and values.

XPath expressions are commonly used in XSLT to select the XML nodes that need to be processed.

Why is XPath Used?

  • To select specific XML elements.
  • To access attribute values.
  • To navigate through the XML document tree.
  • To select nodes based on conditions.
  • To find specific information in XML documents.
  • To select data during XSLT transformations.

Example XML Document

<catalog>

    <book id="b101">

        <title>Learning XML</title>

        <author>Asha Rao</author>

        <price>450</price>

    </book>

    <book id="b102">

        <title>Data on the Web</title>

        <author>Neil Patel</author>

        <price>525</price>

    </book>

</catalog>

Basic XPath Expressions

XPath Expression Meaning
/ Selects from the document root.
/catalog Selects the catalog root element.
/catalog/book Selects book elements directly inside catalog.
//book Selects book elements anywhere in the document.
/catalog/book/title Selects title elements inside book elements.
//title Selects all title elements.
//book/@id Selects id attributes of book elements.
//book[1] Selects the first book child of its parent.
//book/title/text() Selects the text inside book titles.

XPath Axes and Navigation

XPath provides axes that help navigate relationships between nodes in an XML document.

Axis Purpose
child Selects child nodes.
parent Selects the parent node.
self Selects the current node.
ancestor Selects ancestor nodes.
descendant Selects descendant nodes.
following-sibling Selects sibling nodes that appear after the current node.
preceding-sibling Selects sibling nodes that appear before the current node.

XPath Predicates

Predicates are conditions written inside square brackets. They are used to filter selected nodes. 

/catalog/book[1]

/catalog/book[price > 500]

//book[@id="b101"]

//book[title="Learning XML"]

These expressions select:

  • The first book element.
  • Books whose price is greater than 500.
  • The book with ID b101.
  • The book with the title Learning XML.

XPath Functions

Function Purpose
text() Selects text nodes.
position() Returns the position of the current node.
last() Returns the number of nodes in the current selection.
count() Counts selected nodes.
contains() Checks whether a string contains another string.
starts-with() Checks whether a string starts with a specified value.

Example Using XPath Functions

count(//book)

last()

//book[position()=1]

//book[contains(title, 'XML')]
Remember: XPath is used to select and navigate XML nodes. XSLT uses XPath expressions to decide which elements and values should be processed.

8. XSL and XSLT – XML Transformation

What is XSL?

XSL stands for Extensible Stylesheet Language. It is a family of technologies used to work with and transform XML documents.

XSL provides ways to select, transform and format information stored in XML.

Main Components of XSL

Component Full Form Purpose
XSLT Extensible Stylesheet Language Transformations Transforms XML into another format.
XPath XML Path Language Selects elements and values from XML.
XSL-FO XSL Formatting Objects Describes formatting for paginated output, such as print documents.

What is XSLT?

XSLT stands for Extensible Stylesheet Language Transformations. It is used to transform an XML document into another format, such as HTML, XML or plain text.

XSLT reads the source XML document, selects information using XPath and applies template rules to create the output.

Why is XSLT Used?

  • To convert XML data into HTML pages.
  • To transform one XML structure into another.
  • To display XML information in a readable format.
  • To select and arrange specific data.
  • To create reports and tables from XML data.

How XSLT Works

  1. An XML document is provided as the source.
  2. An XSLT stylesheet contains transformation rules.
  3. XPath selects the required XML elements and attributes.
  4. XSLT applies templates to the selected information.
  5. A new output document is generated.

Important XSLT Elements

XSLT Element Purpose
xsl:stylesheet Root element of an XSLT stylesheet.
xsl:template Defines a rule for matching nodes.
xsl:value-of Extracts a selected value.
xsl:for-each Repeats instructions for selected nodes.
xsl:if Applies instructions when a condition is true.
xsl:choose Provides conditional choices.
xsl:sort Sorts selected nodes.
xsl:output Specifies the output format.

Understanding xsl:template

The xsl:template element defines a set of instructions that should be applied when a selected node matches the specified pattern. 

<xsl:template match="/">

    <h2>My XML Data</h2>

</xsl:template>

The match="/" expression selects the document root.

Understanding xsl:value-of

The xsl:value-of element extracts the value of a selected XML node and places it in the transformation output. 

<xsl:value-of select="catalog/book/title"/>

This selects the text value of the title element in the specified path.

Understanding xsl:for-each

The xsl:for-each element repeats a block of instructions for every node selected by its XPath expression. 

<xsl:for-each select="catalog/book">

    <p>

        <xsl:value-of select="title"/>

    </p>

</xsl:for-each>

This example creates a paragraph for every book element and displays its title.

Using xsl:if

The xsl:if element is used to display output only when a specified condition is true. 

<xsl:if test="price > 500">

    <p>Expensive Book</p>

</xsl:if>

Using xsl:choose

The xsl:choose element is used when different output is required depending on multiple conditions. 

<xsl:choose>

    <xsl:when test="price > 500">
        <p>High Price</p>
    </xsl:when>

    <xsl:otherwise>
        <p>Normal Price</p>
    </xsl:otherwise>

</xsl:choose>

Complete Example: XML to HTML Table

The following example converts an XML catalog into an HTML table using XSLT.

Step 1: Create catalog.xml

<?xml version="1.0" encoding="UTF-8"?>

<catalog>

    <book id="b101">

        <title>Learning XML</title>

        <author>Asha Rao</author>

        <price>450</price>

    </book>

    <book id="b102">

        <title>Data on the Web</title>

        <author>Neil Patel</author>

        <price>525</price>

    </book>

</catalog>

Step 2: Create catalog.xsl

<?xml version="1.0" encoding="UTF-8"?>

<xsl:stylesheet version="1.0"

    xmlns:xsl="http://www.w3.org/1999/XSL/Transform">

    <xsl:output method="html" indent="yes"/>

    <xsl:template match="/">

        <html>

        <body>

            <h2>Book Details</h2>

            <table border="1">

                <tr>
                    <th>ID</th>
                    <th>Title</th>
                    <th>Author</th>
                    <th>Price</th>
                </tr>

                <xsl:for-each select="catalog/book">

                    <tr>

                        <td>
                            <xsl:value-of select="@id"/>
                        </td>

                        <td>
                            <xsl:value-of select="title"/>
                        </td>

                        <td>
                            <xsl:value-of select="author"/>
                        </td>

                        <td>
                            <xsl:value-of select="price"/>
                        </td>

                    </tr>

                </xsl:for-each>

            </table>

        </body>

        </html>

    </xsl:template>

</xsl:stylesheet>

Expected HTML Output

ID Title Author Price
b101 Learning XML Asha Rao 450
b102 Data on the Web Neil Patel 525

Explanation of the Example

  • xsl:stylesheet: Declares the XSLT stylesheet.
  • xsl:output: Specifies HTML as the output format.
  • xsl:template match="/": Starts transformation at the document root.
  • xsl:for-each: Processes each book element.
  • xsl:value-of: Extracts the ID, title, author and price.
  • @id: Selects the id attribute of the book element.
Important: XSLT creates a transformed result. It does not change the original XML source document.

9. Connecting XML with XSLT and Running Transformations

Connecting an XML File to an XSLT Stylesheet

An XML document can be connected to an external XSLT stylesheet using an XML stylesheet processing instruction.

This instruction is written after the XML declaration and before the root element.

Example of XML with an XSLT Processing Instruction

<?xml version="1.0" encoding="UTF-8"?>

<?xml-stylesheet
    type="text/xsl"
    href="catalog.xsl"?>

<catalog>

    <book id="b101">

        <title>Learning XML</title>

        <author>Asha Rao</author>

        <price>450</price>

    </book>

</catalog>

Here:

  • xml-stylesheet: Connects the XML document to a stylesheet.
  • type: Identifies the stylesheet media type.
  • href: Specifies the location of the XSLT file.

Files Required for the Example

Save the XML and XSLT files in the same folder: 

XML-Example/
|
|-- catalog.xml
|
|-- catalog.xsl

Open catalog.xml in a browser that supports the XML stylesheet processing instruction and the corresponding XSLT functionality.

Using xsltproc

xsltproc is a command-line tool provided by libxslt. It can be used to transform XML documents using XSLT stylesheets. 

xsltproc catalog.xsl catalog.xml

The command reads catalog.xml, applies catalog.xsl and writes the transformed output to the terminal.

Saving the Transformed Output

The output can also be redirected into a separate HTML file. 

xsltproc catalog.xsl catalog.xml > output.html

The transformed HTML can then be opened in a browser.

Browser-Based XML Transformation

Some browsers provide an XSLTProcessor API that can parse XML and XSLT documents and perform transformations.

A browser-based process generally involves:

  1. Reading the XML document.
  2. Reading the XSLT stylesheet.
  3. Parsing both documents.
  4. Creating an XSLT processor.
  5. Applying the transformation.
  6. Displaying the transformed result.
Compatibility Note: Browser support for XSLT is changing. Chromium currently warns that its browser XSLT support is deprecated and may be removed. For a reliable local demonstration, use an appropriate XSLT processor such as xsltproc. Browser transformation is not a replacement for XML validation.

Difference Between XML Parsing, Validation and Transformation

Process Purpose
Parsing Reads XML and checks basic well-formedness.
Validation Checks XML against a DTD or XSD grammar.
Transformation Converts XML into HTML, XML or another output format using XSLT.

  • XML tags are case-sensitive.
  • Every XML element must be properly closed and nested.

  • DTD defines the legal structure of an XML document.

  • XPath is used to select and navigate XML nodes.

  • XSLT transforms XML into HTML, XML or text.

Final Learning Point

XML provides a standard way to represent and exchange structured information. DTD and XSD define the rules that XML documents must follow, while XPath selects the required information and XSLT transforms it into another format.

Understanding XML structure, syntax, validation and transformation provides a strong foundation for working with structured data and web technologies.
